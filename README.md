# 财务中心 · yc-finance-web

星逸平台第 9 个系统。一期范围：**系统整体结构 + 工具箱（T1 资金日报、T2 流水转凭证、T3 对账核对、T4 日损益速算）**。

---

## 快速启动

```bash
cd yc-finance-web
node server.js 5190
```

打开 http://localhost:5190

> 端口说明：5173 / 5180 / 5181 已被其他系统占用，默认改用 **5190**。
> 也可以不启服务器，直接双击 `index.html` 打开——所有功能都在浏览器端运行。

**零依赖**：不需要 `npm install`，没有构建步骤，只用 Node 内置模块。

## T2 的设计要点

### 支持格式
`.xlsx` / `.csv` / `.tsv` / `.txt`，UTF-8 与 **GBK 自动识别**（国内网银导出常见 GBK）。

xlsx 解析用浏览器内置的 `DecompressionStream` 实现 ZIP 解压，**不依赖任何第三方库**。

### 自动识别
- **表头定位**：银行流水前几行常是账号、户名等说明，工具扫描前 12 行按关键词密度自动定位真正的表头
- **列映射**：10 个字段各有别名表（如日期 = 交易日期 / 记账日期 / 业务日期…），自动匹配后可人工调整
- **金额形态**：支持「收入/支出双列」「发生额 + 借贷标志」「带正负号金额」三种

### 匹配规则

匹配**只看摘要**。对方户名容易误命中——例如「交通运输部」含「运输」会错配到物流费规则——所以对方户名必须由规则显式声明 `scope: 'both'` 才纳入匹配范围。

界面上每笔都显示「**匹配依据**」列，写明是靠摘要还是对方户名命中的。

### 不猜
匹配不上的一律进例外清单，**绝不猜科目**。例外可逐条人工指定，并勾选「存为规则」沉淀进规则库——**用得越久越准**。

### 输出
- **凭证导入 CSV**：15 列（日期·凭证字·凭证号·摘要·科目编码·科目名称·借方·贷方·主体·业务线·项目·合同号·对方户名·流水号·账号），自动校验借贷平衡
- **例外清单 CSV**：未匹配的单独导出，人工在账务系统处理

### 合规提示内置
主体间调拨命中时会打出警告「主体间调拨须走专用审批流」——这是方案里的最高风险项（未清账导致税务注销困难），在工具层就提示。

## T2 规则库按主体隔离

**不同主体业务完全不同，共用一套规则必然记错账。** 规则库、科目表、项目、业主名单都按主体分开存。

目前只有 **优栖（广州）服务管理有限公司** 有规则库，从 2026年第8期真实凭证反推而来。其余 12 个主体（电商、集包、塑料制造等）需要各自提供真实凭证来学。

选到没有规则库的主体时，工具会明说「全部会进例外」，不假装能处理。

### 优栖的业务模式：二房东

从业主手里租房付租金（成本）→ 转租给租客收租金（收入）。两个项目：

| 项目 | 科目后缀 |
|---|---|
| 冼村复建房六期 | `_2001` |
| 花都UU公寓 | `_1001` |

科目里写 `5402_{p}`，`{p}` 按摘要/户名识别到的项目自动替换。

### 业主名单：解决「摘要没有业务含义」

银行流水里付业主租金的摘要是「**跨行汇款**」「**网转**」——纯粹是银行的交易类型，一点业务信息都没有。业务含义全在**对方户名**里。

所以从凭证里提取了 23 个业主名单，**户名命中名单 + 付款方向 = 直接判定付业主租金**，完全不看摘要。

```
跨行汇款 / 卢尤满  →  5402_2001 其他业务成本（靠业主名单）
网转 / 潘妙春      →  5402_2001 其他业务成本（靠业主名单）
```

### 三条从真账学到的口径

**① 平台提现是冲应收，不是确认收入。**
「收花都租金收入（寓小二提现）」记 `1122 应收账款`——租金在挂应收时已确认过收入。规则顺序上，提现必须排在收租金前面，否则会误记成收入。

**② 收租金与收水电费都要拆销项税。**
```
借：银行存款
贷：主营业务收入
贷：应交税费_应交增值税_销项税额
```
按 1% 征收率自动拆分，生成三行凭证。

**③ 退押金用红字冲收入。**
贷方负数 + 贷方正数，按贵司做法实现。

### 认不出项目时怎么办

「支付银行手续费」这类摘要不含项目信息。步骤 2 可以设**默认项目**——不设的话这类会进例外让人判断，不硬猜。

## T1 资金日报生成器的设计要点

### 定位要诚实

出纳每日盘点 11 个主体/平台资金约 **1.2 小时**。这里面**登各家网银抄余额那步工具省不掉**——工具省的是抄完之后的：汇总、算覆盖倍数、比对昨日、排版、生成发群文本。约 15 分钟。

### 每天只填变动的

预置账户台账（42 户，含银行与平台账户），每天**只填今天动过的**。留空自动沿用上一次余额。

一般户、平台账户很多天不动，每天全填 47 个是浪费。

### 但沿用的必须标出来

**这是本工具最要紧的一条设计。** 三种状态严格区分：

| 状态 | 含义 | 日报里 |
|---|---|---|
| 今日更新 | 今天实抄的 | 正常计入 |
| **沿用上次** | 今天没填，用的旧数 | **单独列出，注明取自哪天** |
| **从未录入** | 一次都没填过 | **不计入合计**，单独列出 |

不区分的话，收报表的人会把陈数当新数。

### 数据不全时不算覆盖倍数

某主体有账户从未录入时，余额是不全的，此时算出的覆盖倍数偏低。工具**不算、也不报红线**，只标「数据不全」。

否则会把「**没抄数**」误报成「**快没钱了**」——这是开发时实测到的真实误报，已修。

### 红线规则

单主体活期余额 ÷ 当月固定支出 < **1.5 倍**时预警（阈值可在界面调）。

这是方案第十二章待老板拍板的第 4 项，改这里等于改口径。

### 输出

**钉钉日报文本**（一键复制）：集团合计 + 较上日 + 分主体余额与覆盖倍数 + 红线预警 + 沿用清单 + 缺数清单。

另可导出 CSV（账户级明细 + 主体汇总）。

## T3 对账单核对器的设计要点

**通用件**：物流账单、一件代发、平台结算、快递集包对账单都能用，五条业务线通吃。

### 输入输出

我方台账 + 对方对账单（两个文件，格式不用统一）→ **三类差异**：

| 类型 | 含义 | 通常原因 |
|---|---|---|
| 己方多 | 我方有、对方没有 | 对方漏计；或我方重复记账 |
| 对方多 | 对方有、我方没有 | 我方漏记；或对方多计费 |
| 金额不符 | 两边都有但金额对不上 | 费率不一致；含税/不含税口径不同 |

**工具只指出差异，不判断谁对。** 拿差异清单去找对方核。

### 两边格式不用统一

表头行位置、列名都可以不一样。实测示例：我方表头在第 2 行、对方在第 3 行；列名是「发生日期 / 金额 / 费用类型」对「结算日期 / 结算金额 / 服务类型」——**全部自动认出来**，认不准可以手工改。

### 两种比对模式

| 模式 | 适用 |
|---|---|
| **逐笔比对** | 一单一行（平台结算单常见） |
| **同键合并** | 一单多行（一件代发、物流账单常把一个订单拆成多条费用） |

选错模式结果会差很远，界面上有说明。

### 匹配键与容差

- 匹配键可用 **1 列**（单号/运单号）或 **2 列**（单号 + 日期）
- 金额容差可调（默认 0.01 元），差在容差内算一致

### 模板复用

把这次的**列对应关系、匹配键、容差、模式**存成模板，按对账对象命名（如「顺丰物流」）。下个月同一家直接套用，不用重新配。

### 实测

示例文件各 8 笔，故意埋了三处差异：

| 埋的差异 | 工具识别 |
|---|---|
| SF20260802001 我方 242 vs 对方 248 | ✅ 金额不符，差 -6.00 |
| SF20260804001 只在我方 310 | ✅ 己方多 |
| SF20260808001 只在对方 132 | ✅ 对方多 |
| 合计差额 | ✅ 172.00 = 310 − 132 − 6 |

## T4 日损益速算表的设计要点

### 三层结构（原生支持，不拍平）

```
第 3 层  事业部汇总   = 天猫 + 特卖平台 + 快手 + 私域
第 2 层  特卖汇总     = 京东自营 + 唯品会 + 京东POP
第 1 层  6 个渠道子表  ← 只有这层需要数据源
```

**第 2、3 层由工具按渠道结构重新聚合，不接受导入、不用跨表引用。**
旧 Excel 在这两层用跨表公式，私域列整体串行 7 行，算出「房租物业水电-公摊 = -659.18 元」的负房租。

### 核心约束：不对齐就禁用汇总

任意两个渠道的取数天数差 > **2 天**时，**禁止生成第 2、3 层汇总**，只允许看单渠道。

理由：六个渠道实际取数天数从 0 到 23 天不等，`SUMIFS` 会把「22 天的私域」和「1 天的天猫」直接相加——数字算得出来，但没有业务含义。**拿去开经营会比没有数更危险。**

导出的 CSV 里，汇总行会写明「已禁用：渠道取数天数不对齐，极差 N 天」，而不是给一个错的数。

### 硬推口径显式标注

京东自营零售成本无数据源，按 `收入 × 45%` 硬推，退货按 `-16%` 硬推——所以它的毛利率是**设定值不是算出来的**。

工具在渠道列表、日损益表、导出文件里都标「含硬推」，日历格子也用红色区分。Excel 里「算出来的」和「设定的」长得一样，这是最容易在经营会上被误读的地方。

### 留空 ≠ 0

- **留空** = 当天没数据，不计入天数，不进汇总
- **0** = 当天确实为零，计入天数

这个区分直接决定汇总能不能用，手工录入界面里有明确提示。

### 工具消化掉的结构差异

| 差异 | 旧 Excel | 本工具 |
|---|---|---|
| 日期列偏移 | 天猫 K 列、京东自营 I 列、私域 E 列，步长还不同 | 内部处理，用户不用记 |
| 行号差异 | 天猫推广费拆多行，京东自营只有第 14 行一行 | 按字段名对齐 |
| 汇总方式 | 跨表公式引用，易串行 | 按渠道结构重新聚合 |
| 缺行处理 | 悄悄取到隔壁行的数 | 直接报「缺某行」 |

### 取数口径

| 渠道 | 项目 | 规则 |
|---|---|---|
| 天猫 | 收入 | 销售单明细账 → **只取「天猫-澳乐旗舰店」**，排除 zzzrest |
| 天猫 | 直通车 | 按**记账时间**归属，不按消耗日 |
| 天猫 | CPS | 按明细表日期列归属 |
| 京东自营 | 收入 | 收入交易概况 → 当日成交金额 |
| 京东自营 | 推广费 | 京准通 → 当日支出金额，**源表为负数需取绝对值** |
| 京东自营 | 成本 / 退货 | **硬推 45% / -16%** |

有源文件的只有天猫和京东自营，其余四个渠道手工录入。

## 数据与安全

- **所有解析在浏览器端完成，文件不上传任何服务器**
- 规则库与处理记录存在浏览器 `localStorage`
- 服务器只做静态文件分发，不接收、不存储任何业务数据

> ⚠️ localStorage 是浏览器本地存储，换电脑/清缓存会丢。接入平台后应改为服务端存储——这也是接入时要做的第一件事。
