# 财务中心审查问题修复规格

## 目标

修复审查中确认的“错误数据被当成成功、导入结果不完整、共享/邮件结果不可信”问题，保证现有 T1/T2/T3/T4 和核算工具在异常输入、状态更新、多人并发时给出可验证的结果。

## 范围

### 必须修复

1. T2 期末余额按真实日期时间排序；同日无法判断顺序时停止自动回写并提示人工确认。
2. T2 账号匹配出现多个候选时禁止自动选第一个。
3. T3 金额解析支持会计括号负数；空值、错误单元格、非法文本必须进入例外而不是转为 0。
4. 发票同号导入允许状态/字段更新；状态为作废的记录不得继续进入汇总。
5. 应付导出保留负的超核金额，与页面显示一致。
6. 固定资产已产生折旧凭证后，禁止无提示修改影响历史折旧的字段，或明确要求重新生成历史凭证；本次采用阻断编辑并提示。
7. 工资导入按身份证号优先、姓名仅在唯一时匹配；同名不同证件必须生成不同员工或进入人工确认。
8. 邮件接口拒绝未知 scope，报告全部收件人结果；SMTP `send_message` 返回的拒收字典必须计为失败。

### 可靠性修复

9. CSV/TSV 分隔符按前若干非空行统计，不受标题行影响。
10. XLSX 按 `workbook.xml` 与 relationships 的真实顺序读取工作表。
11. T4 渠道列表的销售渠道页签保留未出现在部分导入文件中的基础渠道行。
12. 套表和邮件临时文件名使用不可碰撞的随机后缀。
13. 利润表 CSV 删除重复的“税金及附加”行。
14. T1 保存函数返回成功状态，调用方只在真正写入后提示“已保存”。

## 不在本次范围

- 不把 T1/T2/T3/核算模块的浏览器 `localStorage` 整体迁移到服务端；这属于后续多人共享存储项目。
- 不改变 T4 当前共享工作区、锁账和字段 CAS 的数据模型。
- 不更改税务、折旧或往来业务口径；只修复数据完整性、状态处理和导出一致性。

## 设计要点

- 所有修复先添加能够复现原问题的自动化测试，再修改生产代码。
- 金额解析返回带 `valid` 信息的结果，调用方可以区分合法的 0 与无法解析。
- 日期排序使用可比较的日期时间值；无法判断同日顺序时不自动写 T1。
- 邮件响应必须覆盖请求中的每个有效收件人，未知范围在生成附件前直接返回 400。
- 临时文件由 `crypto.randomUUID()` 或等价随机值命名，并在成功/失败路径清理。
- 对旧数据保持兼容：已有正常发票保留原 ID；状态更新通过同号替换或标记作废完成。

## 验收标准

- 每个编号至少有一个回归测试覆盖原始复现；测试在修复前失败、修复后通过。
- 现有 JavaScript/浏览器与 Python 测试全部通过。
- 线上部署后可验证：T4 渠道列表导入、共享保存、T2 同日流水保护、邮件未知 scope 拒绝。
- 最终提交不包含用户已有的 `tests/t4-sync.test.js` 未提交改动。
